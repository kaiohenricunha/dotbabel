# AI review workflow release projection

_Last updated: v4.2.0_

The AI review coordinator declares `deep`, `floor`, and `binding: session` in the adjacent `ai-review.compute.yml`. This applies the approved Deep coordinator requirement as a mandatory release floor. It does not change a worker's separate, stronger floor. The canonical `ai-review.source.yml` remains valid GitHub Actions YAML with no concrete model or private Dotbabel metadata.

`npm run build-plugin` resolves the sidecar through the existing requirement parser, shipped policy and accepted release snapshot. The existing Claude invocation renderer supplies the native flags. The workflow adapter inserts native `--model` and `--effort` arguments into the existing coordinator invocation. The pure materializer writes a comment-stamped YAML projection and deterministic manifest. Missing support, low-confidence mandatory evidence or an unsatisfied floor stops the entire build before replacing output. Generation performs no network call, inference or project activation.

The template and `examples/minimal-consumer/.github/workflows/ai-review.yml` receive identical generated bytes. Action commit pins, the same-repository guard, permissions, `ANTHROPIC_API_KEY`, `@anthropic-ai/claude-code`, the headless settings path and turn limit remain unchanged. Worker configuration remains independent. The current accepted evidence does not classify stable alias representations, so generation retains the resolver's native identifier fallback under ARCH-54. It does not infer alias stability from identifier spelling.

A fresh harness initialization copies the generated workflow and its `.dotbabel-projection.json` into `.github/workflows`. Existing initialization refusal stays in force. A new Dotbabel release does not automatically replace an installed workflow. `dotbabel models status --json` reports `shippedWorkflow` and `installedWorkflow` separately, with `configurationBasis: projection`, tool version, snapshot identity, output digest and `matchesShipped`. A mismatch is information about installed bytes, not an update operation or an effective-session observation.

Workflow projection inspection uses the existing Linux/proc-fd backend. Invalid ownership, altered output, malformed snapshot annotations or an incomplete installation report an unavailable projection. These diagnostics do not enable routing or modify the consumer.
