# Claude plugin release baselines

_Last updated: v4.3.0_

The package build creates native Claude metadata from canonical source artifacts and one accepted release snapshot. It uses the shared resolver and pure materializer. It performs no discovery, inference or project activation. Repeating the build with the same inputs produces the same bytes.

```bash
npm run build-plugin
npm run build-plugin -- --check
dotbabel models status --json
```

The build validates the repository's `plugins/dotbabel/src/model-intelligence/snapshot/release-capabilities.json` before replacing generated output. A missing or invalid snapshot, unsupported exact pin, or unsatisfied mandatory floor stops the build. Snapshot age does not alter generated bytes; the separate snapshot release check enforces the seven-day release gate.

The generated `.dotbabel-projection.json` under `plugins/dotbabel/templates/claude/` records the snapshot identity, original source digest, resolver result digest and generated output digest for every projected artifact. Supporting files retain their existing copy behavior.

A canonical agent floor or pin receives the verified native baseline. A dynamic agent without a mandatory floor inherits the session. Canonical inheritance remains inheritance. Dynamic/floor commands retain the existing P-14 rules; an explicit command pin can bind its native model. Skills receive neither model nor effort because those fields do not bind skill execution.

Until their separate migration, intentional legacy agent and command models remain exact compatibility pins. A model-only agent declaration does not gain an effort override. An independently authored agent effort remains exact. This does not infer a semantic class or a quality rank from an alias. Canonical metadata stays in the source; native templates contain allowlisted runtime fields and an ownership comment.

`models status` reports `shippedBaseline` separately from a validated project-local `.claude/.dotbabel-projection.json`. Both use `configurationBasis: projection`. The report includes snapshot identities and the axes present in generated bytes. A projection is not proof of a running session, current entitlement or effective effort. Missing or modified local projections produce an explicit status. Status performs no refresh or write. Projection inspection currently uses the Linux `/proc/self/fd` backend described in the [snapshot guide](model-intelligence-snapshots.md).

Explicit `dotbabel bootstrap --projections` can install these package baselines through the existing ownership and drift controls. It does not enable project intelligence or adaptive routing. Existing user files remain protected by that installation path. Recommendation, migration and ordinary MAIN routing remain separate consumers.

The Tier 2 integration check loads the actual built plugin in an isolated installed Claude process and stops at initialization before inference. It verifies structural loading and reported snapshot provenance. It does not claim that a generated agent executed or that native effort was observed.

An effort-only legacy agent, including `model: inherit` with an explicit effort, fails with `claude_baseline_effort_model_unverified`. The build cannot validate effort support for an unknown inherited model. Keep a verified concrete legacy model or use a reviewed canonical declaration before rebuilding. The build never silently removes this independent control. Mandatory floors and exact pins also reject low-confidence evidence with `release_requirement_unsatisfied`.
