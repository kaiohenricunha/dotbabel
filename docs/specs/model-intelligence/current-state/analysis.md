# Current State Analysis

> Analysis of the existing system being redesigned.

## System Overview

**Approved by the owner on 2026-09-18.** Drafted on 2026-09-17 from DOC-1 and DOC-2, and every count and citation was re-verified against the repository on 2026-09-18. It records measured facts and makes no design decision.

Model configuration today is a declaration with no resolver (DOC-1, "Model Configuration Architecture Today").

1. **Authored source is the only truth.** 68 artifacts carry the metadata in YAML frontmatter: 24 agents, 37 skills, and 7 commands. 67 declare `model:` and 18 declare `effort:` (DOC-1, Executive Summary). No CLI flag, environment variable, `.dotbabel.json` key, or shipped default can override a value (DOC-1, "Source-of-truth tree").
2. **Validation checks one vocabulary.** The only hard gate accepts `opus | sonnet | haiku | inherit` (`plugins/dotbabel/src/validate-skills-inventory.mjs:10`) and requires `model` on every agent (`:271`, `:296`). No code checks `effort`. Three schemas repeat the model enum (`schemas/agent.schema.json:20-23`, `schemas/skill.schema.json:29-37`, `schemas/command.schema.json:12-15`), and schema errors are warnings only (`plugins/dotbabel/src/build-index.mjs:474-476`). DOC-1 counts 9 independent declarations of the enum.
3. **The shipped templates mirror the values verbatim** (asserted by `plugins/dotbabel/tests/build-plugin.test.mjs:372`).
4. **The discovery index drops both keys.** `plugins/dotbabel/src/build-index.mjs` never reads `model` or `effort`, so `index/artifacts.json` cannot answer a model question.
5. **The fan-out copies the values to the other runtimes.** `.cli/skills` (Codex, Gemini CLI, OpenCode) and `.agents/skills` (Antigravity) keep both keys verbatim. The Copilot generator drops both and warns (`plugins/dotbabel/src/copilot-frontmatter.mjs:46-47,60-61`). DOC-2 corrects DOC-1 here: Copilot 1.0.83 also reads `.claude/skills/` and `.agents/skills/` directly, so the keys reach it intact, while `plugins/dotbabel/src/agents.mjs:238` records that Copilot has no skills directory (DOC-2, finding 5).
6. **The runtime decides, and Dotbabel does not observe.** Dotbabel passes no `--model` and no `--effort` to any CLI (DOC-1, finding 1). `plugins/dotbabel/scripts/handoff-extract.sh` is the only observation path; it covers four runtimes and is wrong for two (`:9`, `:84`, `:275`).
7. **Some policy lives in prose.** `skills/agents-search/SKILL.md:225` fixes the tier order `opus → sonnet → haiku → inherit`. `skills/post-pr-review/SKILL.md:112-113` plans its cost from the tiers of agents that it does not own.

Two working resolvers already exist beside this gap, and both are reuse candidates: the `RUNTIMES` registry with its pure resolvers (`plugins/dotbabel/src/agents.mjs:96-241`), and the layered quality policy with explicit unknown states (`plugins/dotbabel/src/quality/config.mjs:166-189`, `plugins/dotbabel/src/quality/types.mjs:14`).

## Pain Points

**Approved by the owner on 2026-09-18.** The four failure classes are the owner's, from §1. The evidence under each is from DOC-1 and DOC-2, re-verified against the repository.

1. **Inert or inconsistent metadata.** 36 skills declare a `model:` that Claude Code ignores, and skill `effort:` has no observable effect on any runtime (DOC-2, findings 1 and 2).
2. **Claude-specific vocabulary in unrelated runtimes.** The effort set `low | medium | max` (`schemas/skill.schema.json:33-36`) matches no runtime (DOC-1, finding 4). 4 of the 11 Codex models do not support `max`, which 11 skills declare (DOC-2, finding 4; DOC-2 says 12, and a count of the `skills/*/SKILL.md` frontmatter on 2026-09-18 gives 11).
3. **Staleness.** The alias table at `docs/specs/dotbabel-agents/spec/5-interfaces-apis.md:29-31` names retired models, and no check reads it (DOC-1, "Staleness Analysis"). `agy` moved from 1.2.4 to 1.2.5 in under four hours, while `plugins/dotbabel/src/agents.mjs:156,272,279` pins facts to v1.2.4 (DOC-2, finding 11).
4. **No discovery and no advice.** No code path can name the models that a runtime offers, and the shipped CI review runs on the default of the CLI (`plugins/dotbabel/templates/workflows/ai-review.yml:27`).

Structural debt behind those failures (DOC-1, "Duplication Analysis" and "Gaps"): 9 independent declarations of the model enum, the 10 rows of the DOC-1 duplication table, error-message strings hand-copied from the validator set (`plugins/dotbabel/src/validate-skills-inventory.mjs:307-309`), and an `invocation` key that `schemas/agent.schema.json:24-27` declares and nothing reads.

## Preserved Behaviors

The migration may change how Dotbabel represents and resolves model requirements, but it must preserve these observable behaviors unless a later explicit key decision changes them. The owner set this list on 2026-09-17. Each behavior carries a `PB-N` id so that §4 and §6 can refer to it.

- **PB-1**: **Security work keeps a strong-model floor.** `security-auditor`, `security-engineer`, and `security-review` must not be silently downgraded below the capability level represented by their current `opus` declarations (`agents/security-auditor.md:20`, `agents/security-engineer.md:20`, `skills/security-review/SKILL.md:19`). Their future representation may become a semantic floor rather than the literal alias `opus`, but the safety property remains: model churn or runtime translation must not select a weaker configuration merely because it is available. The agents explicitly justify the current choice by the high cost of missed security issues (`agents/security-auditor.md:18`, `agents/security-engineer.md:18`).
- **PB-2**: **`veracity-audit` keeps its current high-compute floor during migration.** Its existing `model: opus` and `effort: max` intent (`skills/veracity-audit/SKILL.md:23-24`) must not be weakened while its delegated-agent topology remains unresolved. The skill dispatches a `data-engineer` agent (`skills/veracity-audit/SKILL.md:32,202`), and no `agents/data-engineer.md` exists. Once that dependency is corrected and the worker-compute model is specified, this pin may be reconsidered explicitly rather than disappearing as a side effect of migration.
- **PB-3**: **`rollback-prod` keeps its model requirement and, more importantly, its human confirmation boundary.** Its current `sonnet` / `medium` declaration (`skills/rollback-prod/SKILL.md:19-20`) may later be represented semantically, but no Model Intelligence recommendation, routing result, automatic mode, or runtime translation may bypass the exact typed `ROLLBACK PROD` confirmation. The skill already states that no model-routing decision may bypass it (`skills/rollback-prod/SKILL.md:62-67`).
- **PB-4**: **`local-attest` continues to inherit rather than acquire a new model requirement.** It declares no `model:` or `effort:` and disables model invocation (`skills/local-attest/SKILL.md:25`). Model Intelligence must not infer a model requirement merely because the artifact participates in the migration. Absence/inheritance remains meaningful state.
- **PB-5**: **Unsupported Copilot metadata continues to be omitted with an explicit warning rather than emitted as if supported.** The current Copilot mapper deliberately drops `model`, `effort`, and related incompatible keys and reports those drops (`plugins/dotbabel/src/copilot-frontmatter.mjs:46-47,60-61`; asserted by `plugins/dotbabel/tests/project-sync.test.mjs:409`). The representation may change, and the newly discovered cross-tree auto-discovery leak must be fixed (DOC-2, finding 5), but the safety rule remains: Dotbabel must not knowingly emit unsupported runtime metadata silently.
- **PB-6**: **The shipped AI review workflow remains explicitly bound to the Claude/Anthropic execution path unless §4 makes a separate decision to generalize it.** It invokes `@anthropic-ai/claude-code` and authenticates through `ANTHROPIC_API_KEY` (`plugins/dotbabel/templates/workflows/ai-review.yml:8,25,27`). Model Intelligence must not accidentally reinterpret that provider/runtime choice during generic artifact migration. Whether the workflow also consumes Model Intelligence for its concrete model/effort is a separate open key decision.
- **PB-7**: **Existing explicit pins remain explicit until intentionally migrated.** A pin must not become `dynamic` merely because the new system supports dynamic resolution. Migration preserves the distinction between "the owner intentionally selected this configuration" and "this happened to be the old default."
- **PB-8**: **Existing inheritance remains inheritance.** An omitted model, explicit `inherit`, or equivalent runtime-native inherited state must not be converted into a concrete model during migration unless the owner explicitly chooses a requirement. This prevents Model Intelligence from introducing compute policy where Dotbabel previously delegated the choice to the session/runtime. DOC-2 measured `inherit` as behaviorally identical to an omitted key on a Claude Code agent (DOC-2, "Claude Model and Effort Precedence", cases C and D).

Broader behaviors:

- **PB-9**: **User control over active compute.** Model Intelligence remains advisory at runtime. It may recommend escalation or de-escalation, but it does not silently switch the user's active model or reasoning configuration (ARCH-10).
- **PB-10**: **Runtime-native semantics.** Migration preserves the actual binding behavior that the empirical investigation established. In particular, Claude agent model declarations bind the subagent, command model declarations affect the session, and skill model declarations do not become magically effective merely because the schema changes (DOC-2, "Precedence, derived").
- **PB-11**: **Warnings must not become silent degradation.** Where Dotbabel currently detects an incompatible or dropped declaration, the new system may replace that warning with a more precise diagnostic, but it must not replace it with silent loss.
- **PB-12**: **Generated/runtime fan-out remains derived from Dotbabel source artifacts.** Model Intelligence may change what is emitted per runtime, but generated runtime-specific files remain derived outputs rather than independent model-policy sources.
- **PB-13**: **Safety pins are floors, not market-name commitments.** Preserving `opus` behavior does not mean preserving the literal string `opus` forever. The permanent invariant is the required capability/safety level; literal aliases may be replaced once the resolver can prove an equivalent or stronger runtime-native configuration.
