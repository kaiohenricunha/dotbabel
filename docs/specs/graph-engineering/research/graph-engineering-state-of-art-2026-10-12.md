# Graph Engineering: Community State of the Art — 2026-10-12

An evidence-based survey of what the agent community treats as the standard for graph engineering (multi-agent coordination), and how dotbabel's fleet compares.

## Scope

**Included:** published framework documentation (LangGraph, Microsoft Agent Framework, Google ADK), open protocols (A2A 1.0, OpenTelemetry GenAI conventions), research on concurrent coding agents, and dotbabel's coordination features (`docs/fleet.md`, `dotbabel pr-stack`, `dotbabel task`, the run receipt).

**Excluded:** benchmarks of framework speed, vendor products without public docs, and a code-level review of the fleet hooks. Secondary blog claims are labeled as such and are not used as the basis of a finding.

**Definition used.** Graph engineering designs the topology of a multi-agent system: which nodes exist (agents, functions, routers, joins, human checkpoints), which transitions are allowed, and who owns the runtime graph state. The harness runs one agent loop. The graph is the layer above it ([TrueFoundry](https://www.truefoundry.com/blog/graph-engineering-enterprise-guide)).

## Findings

### 1. There is no single standard, but the frameworks converge

| Item                                            | Status    | Details                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One agreed standard                             | Absent    | The terms are still unsettled. Sources disagree on where the harness ends and the graph begins ([Emergent Mind](https://www.emergentmind.com/topics/multi-agent-harness), [TrueFoundry](https://www.truefoundry.com/blog/agent-harness-vs-agent-framework-whats-actually-different)).                                                                                                         |
| Explicit directed graph of nodes and edges      | Converged | Microsoft Agent Framework runs "a directed graph of executors connected via edge groups" in Pregel-style supersteps ([MS Learn](https://learn.microsoft.com/en-us/agent-framework/concepts/workflows/)). LangGraph compiles a `StateGraph` of nodes and edges. ADK 2.0 adds graph workflows (secondary sources only).                                                                         |
| Typed edge kinds                                | Converged | Direct, conditional, switch-case, fan-out, and fan-in edges. Sequential, concurrent, handoff, and group-chat patterns are prebuilt graphs on the same primitives.                                                                                                                                                                                                                             |
| Topology fixed at plan time, run by a scheduler | Common    | "Task assignment is fixed during planning, with runtime execution performed by a deterministic scheduler" ([Emergent Mind](https://www.emergentmind.com/topics/multi-agent-harness)). A position paper argues a plain agent loop is "a single ready unit scheduler" and proposes an explicit static DAG ([arXiv 2604.11378](https://arxiv.org/abs/2604.11378), no implementation or results). |

### 2. Durable state and human checkpoints are table stakes

| Item                                 | Status   | Details                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Checkpoint at step boundaries        | Standard | Microsoft creates a checkpoint "at the end of each superstep", capturing executor states, pending messages, pending requests, and shared state ([MS Learn checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints)). LangGraph checkpointers persist a thread's state under a `thread_id` ([LangChain docs](https://docs.langchain.com/oss/python/langgraph/checkpointers)). |
| Resume needs stable node identity    | Standard | A rehydrated workflow "must preserve the topology and executor identities of the workflow that created the checkpoint" (MS Learn).                                                                                                                                                                                                                                                                        |
| Checkpoint store is a trust boundary | Standard | "Never load checkpoints from untrusted or potentially tampered sources" (MS Learn).                                                                                                                                                                                                                                                                                                                       |
| Human-in-the-loop as a pause state   | Standard | LangGraph `interrupt()` pauses a node and resumes with `Command(resume=...)`, and it requires a checkpointer ([LangChain interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)).                                                                                                                                                                                                        |

### 3. Open protocols for the cross-agent layer

| Item                          | Status                       | Details                                                                                                                                                                                                                                                                                  |
| ----------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agent-to-agent task lifecycle | Standard, v1.0.0             | A2A defines `SUBMITTED`, `WORKING`, `INPUT_REQUIRED`, `AUTH_REQUIRED`, `COMPLETED`, `FAILED`, `CANCELED`, `REJECTED`. Four are terminal and two are "interrupted" states. Bindings: JSON-RPC, gRPC, HTTP+JSON ([A2A spec](https://a2a-protocol.org/latest/specification/)).              |
| A2A vs MCP split              | Consensus                    | A2A is agent-to-agent coordination, MCP is agent-to-tool access (secondary explainers).                                                                                                                                                                                                  |
| Trace vocabulary              | Emerging, Development status | OpenTelemetry GenAI defines `create_agent`, `invoke_agent`, `invoke_workflow`, `plan`, and `execute_tool` operations ([OTel agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md)). It is marked "Status: Development". |

### 4. Concurrent coding agents on one repository

| Item                                                            | Status          | Details                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Measured conflict rate                                          | Evidence        | 33,596 agent PRs in 2,807 repositories. Textual conflict rate 19.8% for pairs from one agent and 41.7% across agents. Source files are 84.4% of conflicts, lockfiles 3.9%. The authors call these lower bounds and ask for "programmatic orchestration mechanisms for coordinating concurrent agents" ([Xu, Subramanian, Karthik 2026, arXiv:2607.04697](https://arxiv.org/abs/2607.04697); numbers checked against the abstract). |
| Worktree per agent                                              | Common practice | Isolates disk state but "does not prevent the merge conflicts" (practitioner guides).                                                                                                                                                                                                                                                                                                                                              |
| Non-overlapping file ownership                                  | Common practice | Practitioner guidance, not from the study.                                                                                                                                                                                                                                                                                                                                                                                         |
| Merge one at a time, in dependency order, then integrated tests | Common practice | Practitioner guidance, not from the study.                                                                                                                                                                                                                                                                                                                                                                                         |

### 5. dotbabel against the standard

| Standard element                       | dotbabel           | Evidence                                                                                                                                                                                                                    |
| -------------------------------------- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Worktree per agent                     | Yes                | Rule floor "Worktree discipline"; eight checkouts in `git worktree list` on 2026-10-12.                                                                                                                                     |
| File ownership                         | Yes, advisory      | First edit claims the file, a peer edit is denied (`docs/fleet.md:25-35`). Claims are keyed per repository across all worktrees (`docs/fleet.md:40-44`).                                                                    |
| Serialized merge                       | Yes                | Merge token: one session at a time rebases, attests, and merges (`docs/fleet.md:444-449`).                                                                                                                                  |
| Base-moved notice                      | Yes                | Event feed tells claimants which merged files they must rebase over (`docs/fleet.md:324-341`).                                                                                                                              |
| Explicit DAG with topological schedule | Partial            | Only for stacked PRs: `buildStackGraph` and `planStack` with `topoOrder` (`plugins/dotbabel/src/pr-stack.mjs:240`, `:445-446`).                                                                                             |
| Dependencies between units of work     | No                 | Task state has no dependency field (0 matches for `depends_on` or `blocked_by` in `plugins/dotbabel/src/task-state.mjs`).                                                                                                   |
| Durable step state and resume          | Yes                | `dotbabel task` keeps durable state the SessionStart hook prints (`plugins/dotbabel/bin/dotbabel-task.mjs:2-7`). The run receipt is an append-only record of conductor phases (`plugins/dotbabel/src/run-receipt.mjs:2-7`). |
| Human checkpoint                       | Yes, by convention | The conductor stops "with a go/no-go summary" and "never merges" (`skills/pr-conductor/SKILL.md:15-16`). No machine-readable interrupted state.                                                                             |
| Standard lifecycle vocabulary          | No                 | Phase outcomes use a dotbabel vocabulary (`pr-stack record --outcome`, `plugins/dotbabel/bin/dotbabel-pr-stack.mjs:23`).                                                                                                    |
| Standard tracing                       | No                 | 0 matches for `opentelemetry` or `gen_ai.` in `plugins/dotbabel/src`.                                                                                                                                                       |
| Machine resource scheduling            | Ahead of the field | CPU lanes queue heavy tests and pin them with `taskset` (`docs/fleet.md:179-200`). None of the surveyed frameworks covers this.                                                                                             |

## Issues

| Severity | Issue                                                                                                                                                              | Location                                                    | Recommendation                                                                                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WARNING  | No planning-time dependency graph across sessions. A session cannot see that its work waits on another's and pick a non-blocking task.                             | `plugins/dotbabel/src/task-state.mjs` (no dependency field) | Add `depends_on` to task state, and show ready and blocked tasks on `fleet board`. Add a small topological sort; `topoOrder` in `pr-stack.mjs` sorts only pull request numbers (`:339-353`). |
| WARNING  | The merge token does not queue, so merge order is first-to-retry, not dependency order.                                                                            | `docs/fleet.md:514-515`                                     | Queue waiters, and order them by the `pr-stack plan` order when PRs are stacked.                                                                                                             |
| WARNING  | Claims miss writes made through Bash, while source files cause 84.4% of measured conflicts. This audit file was itself written by a heredoc, so it holds no claim. | `docs/fleet.md:162-164`                                     | Detect writes at commit time, as a pre-commit or `post-tool` diff check against peer claims.                                                                                                 |
| INFO     | No OpenTelemetry GenAI spans. Receipts and events are dotbabel-only JSON.                                                                                          | `plugins/dotbabel/src`                                      | Emit optional `invoke_workflow` and `invoke_agent` spans from the receipt writer. Pin to a version, since the spec is Development.                                                           |
| INFO     | Phase outcomes are not mapped to a standard lifecycle.                                                                                                             | `plugins/dotbabel/bin/dotbabel-pr-stack.mjs:23`             | Document a mapping to A2A `TaskState`, with owner-wait as `INPUT_REQUIRED`.                                                                                                                  |
| INFO     | No cross-repository coordination.                                                                                                                                  | `docs/fleet.md:40-44`                                       | Low value: sessions in different repositories rarely share files. Fair CPU share already acts in every repository (`docs/fleet.md:410-422`).                                                 |

## Summary

The community has no single graph-engineering standard. It has converged on explicit node-and-edge graphs, checkpoints at step boundaries, human interrupts as pause states, A2A 1.0 for agent-to-agent tasks, and a still-in-development OpenTelemetry trace vocabulary. dotbabel's fleet matches or beats the coding-agent subset at runtime: worktrees, file claims, a serialized merge, a base-moved feed, durable task state, and CPU lanes. It lacks the planning half: a dependency graph of work, a queued merge order, and standard telemetry. The best next action is a `depends_on` field in task state, surfaced on `fleet board`.
