# §2 — Scope

> What's in, what's out, and where are the boundaries?

## In Scope

One spec, delivered in three phases:

- **Phase 1 — Work graph:** `depends_on`, a task index, and a graph view. A dependency can name work in another repository.
- **Phase 2 — Host adapters:** the fleet behind per-host adapters. Phase 2 also adds a merge queue that the Phase 1 graph orders, and CPU lanes on systems other than Linux.
- **Phase 3 — Decider:** a decider interface, with Jev as an opt-in adapter. The decider covers three judgment steps:
  - review triage: auto-valid, auto-false-positive, or full validation;
  - the conductor's retry choice after a failed phase, inside the existing attempt cap;
  - reviewer dispatch, where the decider may only add reviewers.

  Phase 3 also exports task states as A2A task states and decisions as OpenTelemetry spans.

This scope was chosen on 2026-10-12 with two accepted trade-offs, R-1 and R-2 in §8.

## Out of Scope

- **A general workflow engine** with nodes, edges, and supersteps. dotbabel is the verification layer (`README.md:13-14`), and frameworks such as LangGraph already provide engines (DOC-8).
- **Any model call or network call in the default path** of the code this spec adds (ARCH-3). A model-backed decider is opt-in only (§1 What).
- **Decider answers used as gate evidence,** or as a reason to skip verification. An answer that an agent requests and records cannot prove that verification ran (DOC-9).
- **Model-tier routing.** The model-intelligence spec owns it as in-scope item 6, runtime advisory recommendations (`docs/specs/model-intelligence/spec/2-scope.md:16`). Its code may call this spec's decider as an optional input. Decided on 2026-10-12.

`spec.json` `linked_paths` holds only the code and schema files of the phase in progress. It gains the next phase's files when that phase starts (R-1). Shared documents, such as `docs/cli-reference.md`, stay out of `linked_paths`, because many unrelated pull requests edit them.
